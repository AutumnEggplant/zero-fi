Connecting

Finding it on the network

Zero-Fi broadcasts an open WiFi access point named Zero-Fi-XXXX by default, where XXXX is derived from the device's WiFi MAC address — rename it under Settings → Identity, which also renames the hostname, the AirPlay name, and the Bluetooth name to match. Connect to it, then open http://<that name>.local in a browser. If mDNS isn't working, the AP's own gateway address, http://192.168.4.1, goes to the same place. On most phones, tapping the "Sign in to network" prompt that pops up after connecting takes you straight there too.

The web toolbar lets you play/pause, adjust volume, and switch Bluetooth mode. The Settings link opens the full configuration page.

Joining your home network (optional)

Settings → Network → Home WiFi. Enter your network credentials and save. Zero-Fi will join as a client while keeping its access point running (AP+STA mode). If it loses the connection and can't reconnect, the AP stays up — you won't get locked out.

Once Zero-Fi has a real home-network connection, Settings becomes reachable only from that network — opening it over the AP just bounces you back to the toolbar. There's no setting to change this; it keeps an open guest AP from doubling as an admin backdoor.

Playback

AirPlay

Zero-Fi appears in the AirPlay device list, under its configured name (Settings → Identity), on any iPhone, iPad, or Mac on the same network. Select it from Control Center or the Music app — audio routes to Zero-Fi immediately. Volume can be adjusted from your device or from the Zero-Fi toolbar.

AirPlay and mpd playback are independent; AirPlay audio goes directly through PipeWire and doesn't interact with the mpd queue.

myMPD (built-in web player)

A full-featured mpd web client is bundled, embedded directly in the toolbar, and also reachable on its own at port 8080 (http://<hostname>:8080/). It handles browsing the library, managing the queue, playlists, and cover art. Most people won't need a separate client app once the library is synced.

Connecting a client

Point the client at Zero-Fi's hostname (or LAN address if you're on one), port 6600, no password. That's the standard mpd port — any mpd client will work.

Bluetooth

Two modes

Zero-Fi operates Bluetooth in one of two modes, switchable from settings:

Target Your phone or laptop sends audio to Zero-Fi — useful when you want to stream from a non-AirPlay app (Spotify, podcasts, etc.) to the local speaker.

Source Zero-Fi sends its audio output to a Bluetooth speaker or headphones — useful when the speaker you want to use is Bluetooth-only.

Pairing (Target mode)

Pair from your device's Bluetooth settings — find Zero-Fi (under its configured name, see Settings → Identity) in the device list and pair normally. Zero-Fi auto-accepts pairing requests when in Target mode. You don't need to do anything in Zero-Fi's UI to initiate pairing.

Only one device plays at a time. A second device pairing will take over audio from the first. This part may take a couple of tries I'm afraid but it does reset on failure fairly well so a re-try will work.

Pairing (Source mode)

Go to Settings → Bluetooth. Put your speaker or headphones into pairing mode, then tap Scan in Settings. Select the device from the list to pair and connect. Zero-Fi will reconnect to that device automatically on next boot.

Running a sync

Go to Settings → Library → Sync and hit Sync Now. Zero-Fi mounts the share over SMB and copies new files to the music partition. Progress is shown in that card while running. Be especially aware that no sync jobs process while music is playing.

When sync is enabled and a source is configured, Zero-Fi also runs a sync automatically once a day (around midnight). If the device was off at midnight, it catches up on the next boot. The automatic run requires a WiFi client connection to the home network — it won't attempt to reach the source over the AP-only interface.

mpd rescans after sync completes — new tracks are available in the library shortly after.

Do NOT use a NAS account you care about btw! It's going to be a little too exposed on a device that fails public! Read only, scoped to the collection please. Or, you can always just put the card into a card reader and transfer directly; the music partition should be visible and labeled on nearly any computer.

Updating the mpd database

After copying music directly to the card (or on first boot with pre-loaded files), mpd won't see the new tracks until its database is updated. Open myMPD (see Playback above), go to Database in the myMPD menu, and tap Update. It scans for changes without interrupting playback.

Library sync handles this automatically — manual update is only needed when files are added outside of a sync.

How sync works

Sync is a multi-phase pipeline, not a single file transfer. Hitting Sync Now (or the daily timer firing) runs discovery first: it walks the SMB source and creates one qualify job per album directory. The sync worker then processes jobs in priority order:

  1. Qualify — lists the remote files in a directory and emits one compare job for the directory.
  2. Compare — a file missing locally always emits a sync job. A file that already exists locally is otherwise left alone, unless "Check existing files for changes" is turned on in the Sync card (off by default) — then it's also re-probed against the source and re-synced if it differs. See below for what that check does.
  3. Sync — copies the file from the SMB share to the music partition. New files are queued ahead of re-synced updates, so a fresh album doesn't wait behind a backlog of re-checks.
  4. Prune — the pipeline can remove local files that were deleted from the source and clean up any directories that become empty, but this isn't currently exposed as a setting, so it doesn't run today.

The queue lives in /run (a tmpfs) and evaporates on reboot — a sync interrupted by a power cycle or reboot just needs to be re-triggered. The progress display in the Sync card shows live per-phase counts.

Jobs deduplicate on dequeue: if the same directory queued twice (e.g. you hit Sync Now again mid-run), the duplicate is silently discarded when the first copy is picked up.

The sync worker stops between batches whenever music starts playing and resumes when it stops. Syncing on a Pi Zero W while playing audio is enough to cause skips — the gate keeps things clean without requiring you to think about it.

When "Check existing files for changes" is on, the comparison reads only the first 64 KB of each file (remote and local) to get its duration and tags, rather than hashing or fully reading it — enough to catch a retag or a re-encode without touching audio content. It's still two subprocess calls per file on the Zero W's single weak core, which adds up over a large library — that's why it's opt-in. Music files change rarely; turn this on after you've retagged or otherwise edited files already on the device, then leave it off the rest of the time.

Supported formats

Anything mpd handles: MP3, FLAC, AAC, OGG Vorbis, Opus, WAV, AIFF, and more. Cover art embedded in files or as cover.jpg / folder.jpg alongside tracks is picked up automatically by myMPD.

Curating your library

Artwork & metadata — beets

beets is a great tool for keeping a local collection tidy. It matches your files against MusicBrainz, corrects tags, renames files consistently, and — most usefully for Zero-Fi — fetches and embeds album art. myMPD picks up embedded artwork automatically, so a beets-organized library just looks right.

The fetchart and embedart plugins are the ones that get cover images embedded into every file — see beets' getting started guide for installation and setup.

Volume normalization — ReplayGain

mpd has built-in ReplayGain support (set to auto by default on Zero-Fi), but it only works if your files are tagged with gain values. beets handles this too via its replaygain plugin — run beet replaygain after import and you're done. Alternatively, loudgain is a fast standalone tagger if you prefer something outside beets.

Once tagged, tracks from wildly different sources (CD rips, vinyl digitizations, YouTube downloads) all play back at a consistent level without touching the volume knob.
